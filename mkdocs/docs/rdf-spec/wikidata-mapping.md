# Wikidata under the Mapping

Wikidata serves as the extensive real-world dataset the mapping is intended to address. Its RDF employs almost every kind of term the mapping covers, and zelph imports Wikidata today from a second source, ensuring the same data can reach a network via two distinct routes that must produce identical nodes. This page examines Wikidata, one datatype at a time: what its RDF writes, which nodes the mapping generates from it, what an expansion delivers upon request, and how the JSON dump reaches the same nodes.

The two sources:

- **Wikidata’s RDF**, written by Wikibase, the platform powering Wikidata. Its **truthy** form features one triple per statement of the best rank, with a simple value serving as the object. Its **full** form adds a node for each statement, incorporating rank, qualifiers, and references, along with a node for every **full value**, which carries what a simple value omits, such as the precision and calendar of a date. The full dumps hold both forms; `Special:EntityData/<id>.ttl?flavor=dump` gives both for a single entity.
- **The JSON dump**, which zelph’s importer reads today via `.load`. Today a network built from it solely by `.load` holds the statements whose value is an item, of any rank, as facts like `Q42 P31 Q5`; the identifier of every entity as its name within `wikidata`; the English label, or the `mul` label if no English one exists, as its name within `en`; a marker indicating how labels were assigned; and nothing further – no dates, quantities, strings, or coordinates, no statement nodes ([zelph and Wikidata](../wikidata.md), [Binary Data Files](../binaries.md), [Wikidata Qualifiers](../qualifiers.md)).

Everything below constitutes specified behaviour, except where a sentence says "today". The Turtle quoted is authentic: exports from `Special:EntityData`, pinned by revision and fetched on 23 November 2026, abbreviated where indicated by the sentence preceding them. The rules for the export were checked against Wikibase’s source at commit `5c00631` from 22 November 2026; a port of its date cleaners and value hashes reproduced all 144 date literals and all 178 full value nodes from nine such exports (measured on 23 November 2026).

The boxes write what the mapping produces from the quoted triples as a script under `.lang zelph` does with Wikidata’s prefixes declared, similar to the [checks](checks.md#what-the-checks-share). A prefixed name arrives at the node that the [namespace table](iris.md#the-rows) gives its IRI: `wd:P569` and `wdt:P569` are both the node `P569` in `wikidata`, `psv:P569` the node named `psv:P569`; an IRI lacking a corresponding row, such as that of a web page, is the node of its full IRI in the IRI language `<iri>`.

    ```
    .prefix wd: <http://www.wikidata.org/entity/>
    .prefix wdt: <http://www.wikidata.org/prop/direct/>
    .prefix p: <http://www.wikidata.org/prop/>
    .prefix ps: <http://www.wikidata.org/prop/statement/>
    .prefix psv: <http://www.wikidata.org/prop/statement/value/>

    .prefix wdno: <http://www.wikidata.org/prop/novalue/>

    ```

Wikibase writes a value using a builder chosen by the datatype of its property (`repo/includes/Rdf/` in Wikibase; the extensions Math and Score add mathematical expressions and musical notation). ## Entities and Statement Nodes

The rows of the [namespace table](iris.md#the-rows) assign to Wikidata’s IRIs the names that `.load` and `.wikidata-qualifiers` attribute to its nodes today. `wd:` and `wdt:` give the bare id, so the truthy triple `wd:Q42 wdt:P31 wd:Q5` is the fact `Q42 P31 Q5` that a network built from the JSON dump already holds, and a script that names `Q42` works with both ([D1](decisions.md#d1)). Wikibase’s remaining namespaces keep Wikidata’s prefix within a name of `wikidata` (`p:P569`, `wds:…`, `wdv:…`, `wikibase:rank`); everything else, ranging from `schema:` to the pages of Wikipedia, stays a node of the IRI language. Douglas Adams (Q42), revision 2569933068 of 15 November 2026, shortened to the statement of his date of birth and two truthy triples:

```turtle
wd:Q42 wdt:P31 wd:Q5 ;
	wdt:P569 "1952-03-11T00:00:00Z"^^xsd:dateTime .

wd:Q42 p:P569 wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F .

wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F a wikibase:Statement,
		wikibase:BestRank ;
	wikibase:rank wikibase:NormalRank ;
	ps:P569 "1952-03-11T00:00:00Z"^^xsd:dateTime ;
	psv:P569 wdv:426df9023763f08b066f4478480f44cd .
```

Each triple becomes one fact having one object ([Statements](iris.md#statements)), Turtle’s `a` serving as the predicate `rdf:type`; the literal in the second and seventh fact is a single value node ([Literals as Value Nodes](literals.md)):

!!! example "Specified – not yet implemented"

    ```
    wd:Q42 wdt:P31 wd:Q5
    wd:Q42 wdt:P569 "1952-03-11T00:00:00Z"^^xsd:dateTime
    wd:Q42 p:P569 wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F
    wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F rdf:type wikibase:Statement
    wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F rdf:type wikibase:BestRank
    wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F wikibase:rank wikibase:NormalRank
    wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F ps:P569 "1952-03-11T00:00:00Z"^^xsd:dateTime
    wds:q42-D8404CDA-25E4-4334-AF13-A3290BCD9C0F psv:P569 wdv:426df9023763f08b066f4478480f44cd
    ```

**Other entity values.** Today `.load` keeps only statements where the value is an item. The JSON route is specified to write those whose value is a property, lexeme, form, sense, or EntitySchema as well, mirroring the RDF behaviour ([D25](decisions.md#d25)): on 4 November 2026 the Wikidata Query Service counted 87,746 such instances, spanning all ranks, found on items and properties (62,729 property values, 13,138 lexemes, 11,507 forms, 120 senses, 252 EntitySchemas), including "subproperty of" (P1647). They arrive as facts and bring no rule. A triple whose predicate is also its object, such as `wd:P1269 wdt:P1659 wd:P1659`, is counted and reported rather than written ([Statements](iris.md#statements), [Open Decisions](open-decisions.md#triples-whose-predicate-is-their-object)); its full form, with the predicate `ps:P1659`, is written.

### Statement Nodes

Wikibase names a statement node after the statement’s id, replacing every character except letters, digits, `_`, and `-` with `-`: the JSON id `q42$D8404CDA-…` becomes `wds:q42-D8404CDA-…`, retaining the lowercase `q` that this id happens to possess. Wikibase documents that "there is no guaranteed format or meaning to the statement id", and since this substitution cannot be undone with certainty, the RDF form serves as the canonical name across both routes ([Statement Nodes](iris.md#statement-nodes)); the JSON route can always apply the replacement.

Today `.wikidata-qualifiers` names a statement node after its JSON id, using `$` ([Data Model](../qualifiers.md#data-model)); with the mapping it writes the `wds:` form. The single published network featuring this layer, `wikidata-20260309-all-P11260.bin` containing 1,476 statement nodes, is regenerated for the release just like every other published network. The layer’s additional names (`p:P2738`, `pq:P11260`, `wikibase:rank`, …) are already the ones specified by the namespace table for Wikibase’s IRIs.

### Ranks

The truthy form holds the **best** statements of a property: the preferred ones if any exist, otherwise the normal ones, never the deprecated ones; the full form holds every statement along with its rank. Neckertal (Q68864), a Swiss municipality, revision 2573354201 of 21 November 2026, features three population figures, two of normal rank and one preferred, and only the preferred one is truthy: `wd:Q68864 wdt:P1082 "+4035"^^xsd:decimal`.

The JSON route keeps every rank ([D25](decisions.md#d25)): today `.load` reads no rank and writes item values across every rank, and this remains unchanged, as the ACE front end documents and tests answers involving every rank ([Words and Wikidata](../ace-spec/words.md)) and the published networks would otherwise shift. The contrast with a network built from the truthy RDF is instead stated: 3,559,395 deprecated statements of item-valued properties (counted on QLever’s Wikidata index of 10 August 2026, queried on 4 November 2026) and approximately 0.73 million normal ones outranked by a preferred one (estimated on 4 November 2026 from a block sample of the JSON dump of 9 March 2026). Imported values carry marks for their rank ([Direct Full-Value Facts](#direct-full-value-facts)).

## Time Values

### What the Export Writes

A point in time in the JSON includes a timestamp, a precision, a time zone, a calendar model, and the fields `before` and `after`. The export writes the cleaned timestamp as the simple value and, at the full value node, repeats it as `wikibase:timeValue`, beside precision and time zone as `xsd:integer` and the calendar’s item as an IRI; `before` and `after` are dropped. Wikidata accepts only precisions from 0 to 11 and the time `00:00:00Z`. Julius Caesar (Q1048), revision 2572162504 of 19 November 2026, has four birth dates and two death dates; five of them:

| JSON timestamp | Precision | Calendar | Export |
|---|---|---|---|
| `-0100-07-12T00:00:00Z` | 10, month | Julian | `-0099-07-01T00:00:00Z` |
| `-0100-07-13T00:00:00Z` | 11, day | Julian | `-0099-07-11T00:00:00Z` |
| `-0102-00-00T00:00:00Z` | 9, year | Julian | `-0101-01-01T00:00:00Z` |
| `-0044-03-15T00:00:00Z` | 11, day | Julian | `-0043-03-13T00:00:00Z` |
| `-0044-00-00T00:00:00Z` | 9, year | Gregorian | `-0043-01-01T00:00:00Z` |

The truthy triples hold the preferred values, located in rows one and four; condensed to them and the full value node from row one:

```turtle
wd:Q1048 wdt:P569 "-0099-07-01T00:00:00Z"^^xsd:dateTime ;
	wdt:P570 "-0043-03-13T00:00:00Z"^^xsd:dateTime .

wdv:d7d2f4ab2e0218889c6f58166c66da23 a wikibase:TimeValue ;
	wikibase:timeValue "-0099-07-01T00:00:00Z"^^xsd:dateTime ;
	wikibase:timePrecision "10"^^xsd:integer ;
	wikibase:timeTimezone "0"^^xsd:integer ;
	wikibase:timeCalendarModel <http://www.wikidata.org/entity/Q1985786> .
```

Decision [D6](decisions.md#d6) states the cleaning in short; Wikibase’s `DateTimeValueCleaner` and `JulianDateTimeValueCleaner` apply these rules:

1. **Form and precision.** The `+` is dropped, and the year maintains a minimum of four digits. Month precision assigns the day as `01`, while year precision and coarser levels set both month and day: 1990 at year precision yields `1990-01-01T00:00:00Z`, the literal for 1 January 1990.
2. **A day exceeding the month’s limit** becomes the month’s final day, applicable to both Gregorian values and Julian values written as Gregorian (rule 4); prior to 4713 BCE, every 29 February remains, even in non-leap years, as an invalid `xsd:dateTime` in such years. A converted Julian value instead rolls over: Julian 30 February 1700 results in `1700-03-12`, matching the outcome of Julian 1 March 1700.
3. **Years preceding the common era** are adjusted to align with XSD 1.1’s count, where 1 BCE is represented as `0000`, at year precision and finer: `-0044` becomes `-0043`. Coarser values keep the JSON’s year representation: a millennium `-4000` remains `-4000`.
4. **Julian values** are translated into the proleptic Gregorian calendar exclusively at day precision, for the JSON’s years −4713 to 1465072, except 1 January 4713 BCE, which PHP’s conversion fails to process; otherwise, they are written as if they were Gregorian. Caesar’s month of birth keeps its Julian digits.
5. **Calendars other than Gregorian** (`Q1985727`) and Julian (`Q1985786`) are cleaned as Gregorian below day precision. At day precision, and for the year 0 at any precision, the cleaner produces no output, and the export writes the JSON’s timestamp unchanged as a plain string, `"+0000-00-00T00:00:00Z"`: 82 values on the Wikidata Query Service on 4 November 2026, 38 with the year 0 and 44 with another calendar, including the item Q199.
6. **The calendar model** at the full value node stays the value’s intrinsic model, even when the literal has been converted.

Wikibase documents the fallback to a string, the conversion, the count of XSD 1.1, and the calendar kept; the rules relying on precision are present solely within the code.

### Reading a Full Time Value

The `wikibase` module registers a class expander for `wikibase:TimeValue` using `zelph:interval` ([Expanders](expansion.md#expanders)). It reads a node’s four statements together and writes the interval that [Wikibase’s Precisions](dates.md#wikibase-precisions) specifies, within the value’s calendar, reversing the effect of the export:

- **Digits and year.** At day precision a Gregorian literal equates to its day; at month precision and coarser the literal holds the JSON’s digits within the value’s calendar, including the Julian one. At year precision and finer the year is counted as in XSD 1.1 (`-0099` represents 100 BCE), below as in the JSON (`-4000` represents 4000 BCE).
- **A Julian value at day precision** underwent conversion: `-0099-07-11` translates to 11 July 100 BCE in the Gregorian calendar, 13 July in the Julian one. Outside the converted range the literal holds Julian digits. Near either end a literal may originate from both – `-4713-11-25` to `-4713-12-31` and `-4712-01-01`, and `1465073-01-01` to `1465103-01-30` – and gets no interval.
- **No interval** either for a plain-string `timeValue`, the year 0, or any other calendar.
- **The time zone is not applied**, and `before` and `after`, which the RDF lacks, are not read on the JSON route either.

Using day numbers derived from the formulas in [Dates](dates.md#day-numbers), a request expands the dates of birth in the table and Douglas Adams’s date of birth:

!!! example "Specified – not yet implemented"

    ```
    psv:P569 zelph:expand-objects zelph:interval
    wdv:d7d2f4ab2e0218889c6f58166c66da23 zelph:interval (&1685080 interval &1685110)
    wdv:538252d382043b5ece2edc2cb9efcff1 zelph:interval (&1685092 interval &1685092)
    wdv:401fa9500ba6ec472672f482ef07862e zelph:interval (&1684168 interval &1684532)
    wdv:426df9023763f08b066f4478480f44cd zelph:interval (&2434083 interval &2434083)
    ```

The first is the Julian July 100 BCE, the second is the day of birth within that month, the third is the Julian year 102 BCE. Month and day overlap and follow neither order ([The Three Relations](dates.md#the-three-relations)), as they ought to.

Two values with a single literal remain as two distinct nodes. Johann Sebastian Bach (Q1339), revision 2572161876 on 19 November 2026, possesses a preferred Julian date of birth, 21 March 1685, and a normal Gregorian counterpart, 31 March 1685. After conversion, the first gets the literal of the second, `"1685-03-31T00:00:00Z"^^xsd:dateTime`, yet the export keeps two full value nodes, `wdv:1361ec7a694d5e3d2da3cee9c2b11755` bearing the calendar `Q1985786` and `wdv:bb50079fb9bbc454270bf96c42174fd2` with `Q1985727`. Both expand to day 2336584, representing the identical day.

### A Truthy Date Has No Interval

A network constructed solely from truthy triples yields no intervals for Wikidata’s dates ([D6](decisions.md#d6)): the truthy literal carries neither precision nor calendar. The generic expansion of `xsd:dateTime` ([Dates](dates.md)) would be wrong below day precision: Caesar’s truthy `"-0099-07-01T00:00:00Z"^^xsd:dateTime` would become an instant on the Gregorian 1 July 100 BCE (day 1685082) for what is actually a Julian month (days 1685080 to 1685110), 1990 at year precision its first of January, and a coarse year before the common era would be misaligned by one year. The module `wikibase` requests no processing for truthy dates, and the checks read full values ([What the Checks Share](checks.md#what-the-checks-share)).

## Quantities

The export writes a quantity’s amount as the simple value, an `xsd:decimal` bearing a sign and lacking a unit. The full value node holds the amount, the bounds if present, and the unit as the IRI of its item; the unit "1" becomes `wd:Q199`, the item representing the number one. Greitnerkogel (Q103844210), a mountain, revision 2499715399 of 30 May 2026, features an elevation with bounds; the number item 113 (Q715432), revision 2573260262 of 21 November 2026, a numeric value without:

```turtle
wd:Q103844210 wdt:P2044 "+774"^^xsd:decimal .

wdv:8011b58e4d7e6eb256aa7c7e1aa0b85b a wikibase:QuantityValue ;
	wikibase:quantityAmount "+774"^^xsd:decimal ;
	wikibase:quantityUpperBound "+776"^^xsd:decimal ;
	wikibase:quantityLowerBound "+772"^^xsd:decimal ;
	wikibase:quantityUnit <http://www.wikidata.org/entity/Q11573> ;
	wikibase:quantityNormalized wdv:8011b58e4d7e6eb256aa7c7e1aa0b85b .

wd:Q715432 wdt:P1181 "+113"^^xsd:decimal .

wdv:4d4bb312a086f8f4ff4186ceb7c54a5d a wikibase:QuantityValue ;
	wikibase:quantityAmount "+113"^^xsd:decimal ;
	wikibase:quantityUnit <http://www.wikidata.org/entity/Q199> .
```

The JSON gives the second the unit `"1"`; the JSON route writes `Q199`, just as the RDF does, so both routes produce a single network ([D11](decisions.md#d11)), and computes the node’s name before replacing the unit ([The Name of a Full Value](#the-name-of-a-full-value)).

- **Amounts** are value nodes of `xsd:decimal` and expand as [Numbers](numbers.md#the-decimal-family) specifies: `"+774"^^xsd:decimal` to `&774`, `"+113"^^xsd:decimal` to `&113`, Douglas Adams’s height `"+1.96"^^xsd:decimal` to `(&196 dec &2)`. A number item with an imported numeric value needs no name reader ([Name Readers](expansion.md#name-readers)).
- **One unit only.** The unit is an item, here `Q11573` (metre) or `Q199`, and every relation between two quantities must first require the same unit node. Simple values carry no unit, and one node `"+774"^^xsd:decimal` serves metres, feet, and inhabitants alike, so no quantity is compared via its simple value.
- **The interval.** The module `wikibase` registers a class expander for `wikibase:QuantityValue` with `zelph:interval`; it writes an interval only when bounds are present, `(&772 interval &776)` for the elevation and none for 113. That interval means "within the stated bounds", as Wikibase leaves their reading open: "it may represent hard limits on the value, or the interval may just describe the 66 or 95 percentile interval of a normal distribution" (Wikibase’s data model). Many stored bounds are not an editor’s statement either: prior to November 2016, Wikibase stored bounds of plus or minus one unit of the last digit with an amount that was entered without any (Phabricator T115269 and T142087), and such guessed bounds remain in the data. A date’s interval, in contrast, is exact: every day the date can mean. The module `intervals` applies the three relations of [Dates](dates.md#the-three-relations) to bounds as well, and a verdict holds relative to the stored bounds.
- **Without bounds** a quantity lacks an interval: its uncertainty is unknown, not zero, and a point would claim what the data does not say. It gets weaker relations over the amount, `amount-lt`, `amount-gt` and `amount-eq` from the module `wikibase` (names in `zelph`), which compare the expanded amounts of two quantities of one unit and never claim certainty. That is the usual case: on 4 November 2026 the Wikidata Query Service held 24,243,660 bounded among 58,903,097 full value nodes of quantities, and only 2.4 % of the heights (P2048) and 4.7 % of the elevations (P2044) had bounds.
- **Normalized quantities** are imported as-is and never expanded. Where Wikibase can convert a unit, the full form adds a node in the standard unit, linked by `psn:`, `pqn:`, or `prn:` and `wikibase:quantityNormalized`; the elevation above is its own normalization. Wikibase performs conversion via a table of factors and rounds amount and bounds to the order of their uncertainty, so a normalized interval need not contain the exact conversion and might conflict with the original. An import that selects its predicates ([Parameters](import.md#parameters)) leaves out the triples of `psn:`, `pqn:`, and `prn:` with a `wdv:` object, as well as those of `wikibase:quantityNormalized`, unless it explicitly names their predicates, and an import of everything holds them ([What Differs by Design](#what-differs-by-design)). Comparison across units is left to a later module that converts exactly, using the conversion statements (P2370) of Wikidata’s units.

## Coordinates, Text and Links

### Coordinates

The export writes a coordinate as `"Point(longitude latitude)"^^geo:wktLiteral`, and at the full value node includes latitude, longitude, and precision as `xsd:double`, along with the globe as an IRI, each number rendered as PHP turns a floating-point number into text: 14 significant digits, exponents in the format `1.0E-6`. Neckertal (Q68864), revision 2573354201, whose JSON contains the latitude 47.333333333333336, the longitude 9.133333333333333, and the precision 0.1:

```turtle
wd:Q68864 wdt:P625 "Point(9.1333333333333 47.333333333333)"^^geo:wktLiteral .

wdv:a35185bc260a62d29a341613c0ca8e15 a wikibase:GlobecoordinateValue ;
	wikibase:geoLatitude "47.333333333333"^^xsd:double ;
	wikibase:geoLongitude "9.1333333333333"^^xsd:double ;
	wikibase:geoPrecision "0.1"^^xsd:double ;
	wikibase:geoGlobe <http://www.wikidata.org/entity/Q2> .
```

Without precision, a coordinate is assigned the class `wikibase:GeoAutoPrecision` and the precision 1/3600 (`0.00027777777777778`); outside Earth, the literal begins with the globe’s IRI, a `>` in it encoded as `%3E`, as in `"<http://www.wikidata.org/entity/Q405> Point(…)"^^geo:wktLiteral` on the Moon.

- **One node on both routes** ([D25](decisions.md#d25)). The JSON’s shortest round-trip digits, `47.333333333333336`, would generate an additional value node and another number, so the JSON route writes PHP’s 14 digits, `wikibase:GeoAutoPrecision` where the precision is missing, and the globe into the literal, just as the export does.
- **A truthy coordinate expands into its components** upon request: the module `wikibase` registers three expanders for `geo:wktLiteral`, one for each predicate of the full value, and a request names the predicate it seeks, as in `wdt:P625 zelph:expand-objects wikibase:geoLatitude` ([Expanders](expansion.md#expanders)). The components are two value nodes of `xsd:double` with the digits from its text, and the globe’s node, connected via the predicates of the full value, whose own value nodes they are; a rule written for full values also reads a truthy coordinate. On 4 November 2026 the Wikidata Query Service held 12,516,205 truthy coordinates (P625).
- **The numbers** come through [Numbers](numbers.md#doubles-and-floats) on a request of their own: `"47.333333333333"^^xsd:double` expands to the exact value of the nearest double, neither 47.333333333333 nor the JSON’s double.

!!! example "Specified – not yet implemented"

    ```
    "Point(9.1333333333333 47.333333333333)"^^geo:wktLiteral wikibase:geoLongitude "9.1333333333333"^^xsd:double
    "Point(9.1333333333333 47.333333333333)"^^geo:wktLiteral wikibase:geoLatitude "47.333333333333"^^xsd:double
    "Point(9.1333333333333 47.333333333333)"^^geo:wktLiteral wikibase:geoGlobe wd:Q2
    ```

### Monolingual Text, Strings and External Identifiers

A monolingual text becomes a value node of `rdf:langString` with its tag, lowercased just as all tags are: Neckertal’s official name is `ps:P1448 "Neckertal"@de-ch`. Only labels become names ([Which Predicates Make a Name](names.md#which-predicates-make-a-name)). The export writes the tag solely when it consists of at least two characters, all of which are letters, digits, or hyphens; otherwise, it emits a plain string, and the JSON route makes the identical check. A string becomes a value node of `xsd:string`, such as Greitnerkogel’s category on Commons, `wdt:P373 "Greitnerkogel"`; musical notation is such a string on both routes, since its extension lacks a builder for values and Wikibase defaults to that for strings. All three expand on request into their constituent characters ([Strings](expansion.md#strings)).

An external identifier is also a plain string, after trimming. When the property includes a pattern for RDF – on Wikidata, its statement "formatter URI for RDF resource" (P1921) – the export adds the normalized IRI, the pattern with `$1` replaced by the URL-encoded identifier, under `wdtn:` next to the truthy triple and under `psn:`, `pqn:`, or `prn:` next to the full one. Douglas Adams (Q42), revision 2569933068:

```turtle
wd:Q42 wdt:P214 "113230702" ;
	wdtn:P214 <http://viaf.org/viaf/113230702> .
```

Neckertal’s `wdt:P771 "3396"` lacks a `wdtn:` triple, as P771 has no pattern. The identifier becomes a value node of `xsd:string`, while the normalized IRI becomes an IRI node. On the JSON route the normalized IRI is derived upon request from the pattern, imported alongside the values of P1921, and never written by default ([D2](decisions.md#d2)): it is an additional node and fact per identifier ([Costs](costs.md)).

### URLs and Files on Commons

A URL is an IRI in the RDF and a string in the JSON: `wdt:P856 <https://douglasadams.com>` there, `"https://douglasadams.com"` here. The JSON route writes the IRI, trimmed as the export trims it, so both routes reach one IRI node; an IRI and a string with matching characters stay two distinct nodes ([An IRI or a String](querying.md#an-iri-or-a-string)). A file on Commons is its IRI under `Special:FilePath`, with the name encoded using PHP’s `rawurlencode`: Greitnerkogel’s image `"Greitnerkogel Waldstein 01.jpg"` becomes `<http://commons.wikimedia.org/wiki/Special:FilePath/Greitnerkogel%20Waldstein%2001.jpg>`. Geographic shapes and tabular data are the IRIs of their respective pages under `http://commons.wikimedia.org/data/main/`, encoded according to MediaWiki’s `wfUrlencode`. The JSON route constructs identical IRIs.

### Mathematical Expressions

A mathematical expression is represented in TeX within the JSON. During execution, the export renders it to MathML and writes the MathML as a literal of `<http://www.w3.org/1998/Math/MathML>`, omitting the original TeX; a TeX string that the renderer refuses becomes an error element. The prime 2147483647·2^3564 + 1 (Q96851780), revision 2328851543 from 22 March 2025, contains the TeX `2147483647 \times 2^{3564}+1`; its export, the MathML shortened:

```turtle
wd:Q96851780 wdt:P2534 "<math class=\"mwe-math-element mwe-math-element-inline mathjax_ignore\" xmlns=\"http://www.w3.org/1998/Math/MathML\">…</math>"^^<http://www.w3.org/1998/Math/MathML> .
```

This is the sole stated exception to the rule that the same value yields the same value node across both routes ([D25](decisions.md#d25)). The MathML cannot be computed from the TeX without the renderer and is contingent upon it, as the classes in its markup show: a new renderer assigns a new literal to the same value. The JSON route writes the TeX as a literal of `<https://zelph.org/ns#TeX>`, the RDF route keeps the MathML, and neither datatype possesses an expander ([Datatypes](literals.md#datatypes)). On 4 November 2026 the Wikidata Query Service held 147,840 such statements across 36 properties.

## Unknown Value and No Value

**An unknown value** manifests as a blank node in dumps and exports. Wikibase labels it with the md5 of the statement’s local name, the IRI of the property’s namespace, the IRI of `wdv:`, and the hash of the snak, ensuring that the truthy and the full triple – whose property namespaces differ – each receive distinct blank nodes. Severus Alexander (Q1769), revision 2573179002 of 21 November 2026, features a father with an unknown identity beside two known ones; shortened:

```turtle
wd:Q1769 wdt:P22 _:9bdf84525ed773079f49f76ed44d41be,
		wd:Q1762,
		wd:Q1446 .

wds:q1769-AC354458-A8B9-41BA-AECB-1421F7C097D5 a wikibase:Statement,
		wikibase:BestRank ;
	wikibase:rank wikibase:NormalRank ;
	ps:P22 _:961a3ba56336f6a17f02e3d9b16c4393 .
```

A blank node takes its id from its label and the document’s identity ([Blank Nodes](blank-nodes.md)). Wikibase’s labels are content hashes and mean the same across all documents, so data from Wikidata maintains a single fixed identity, `http://www.wikidata.org/`: the JSON route always employs it, an RDF import of Wikidata’s data passes it as `identity=`, and the import report issues a warning when encountering Wikibase’s ontology under a different identity ([The Identity of a Document](blank-nodes.md#the-identity-of-a-document)). With the default identity, the file’s path, the two routes would make two nodes of one unknown father.

The JSON route writes an unknown value in the same manner as the truthy form, using `wd:Q1769 wdt:P22` alongside the blank node associated with the truthy label. A dump line lacks a hash for a main snak, yet the hash of an unknown value relies solely on its property – the sha1 of `C:45:"Wikibase\DataModel\Snak\PropertySomeValueSnak":3:{P22}` is `a610af57…`, the hash linked to the export’s label – thus the route computes it. A blank node has no interval; the checks bypass it. The Wikidata Query Service returns an unknown value as an IRI under `http://www.wikidata.org/.well-known/genid/` followed by the identical label, so its outputs deliver IRI nodes of the IRI language ([D1](decisions.md#d1)), which the mapping does not turn back into blank nodes.

**No value** is a class: of the entity for a statement of the best rank lacking a value, of the statement node for each such statement, of the reference node in a reference. Bach (Q1339), revision 2572161876, has a statement P6275 without value:

```turtle
wd:Q1339 a wdno:P6275 .

wds:Q1339-6ab4787d-478f-f3b0-fe80-8adc9671a8da a wikibase:Statement,
		wikibase:BestRank ;
	wikibase:rank wikibase:NormalRank ;
	a wdno:P6275 .
```

!!! example "Specified – not yet implemented"

    ```
    wd:Q1339 rdf:type wdno:P6275
    wds:Q1339-6ab4787d-478f-f3b0-fe80-8adc9671a8da rdf:type wdno:P6275
    ```

`rdf:type` is an IRI node in its own right and not zelph’s `~` ([D21](decisions.md#d21)); the class is the node named `wdno:P6275` within `wikidata`, and the bridge `rdf-types` brings such classes into rules over `~`. The JSON route writes the class at the entity for a statement of the best rank without value, just as the truthy form does.

## Labels, Descriptions, Aliases and Sitelinks

Wikidata’s RDF writes each label three times, using the language code exactly as in the JSON. Douglas Adams (Q42), revision 2569933068, has labels across 75 languages and none in `en`; its label in `mul`:

```turtle
wd:Q42 rdfs:label "Douglas Adams"@mul ;
	skos:prefLabel "Douglas Adams"@mul ;
	schema:name "Douglas Adams"@mul .
```

The three provide a single name, "Douglas Adams" in the language `mul` ([D7](decisions.md#d7), [Labels, Names and Languages](names.md)); `schema:name` makes a name because the subject is a Wikidata entity. `mul` stays a language in its own right, and a lookup in `en` falls back to it ([D13](decisions.md#d13), [`mul`](names.md#mul)). This alters the JSON route: today `.load` copies a `mul` label into `en` when no English label exists, so Q42 is named "Douglas Adams" in `en`; with the mapping, the name resides in `mul`, as it does on the RDF route. The number item 113 (Q715432) carries the label `113` in `en` as well as in `mul`, and receives both names.

At a sitelink, `schema:name` is the article’s title and its subject is the article’s page. From the same export:

```turtle
<https://en.wikipedia.org/wiki/Douglas_Adams> a schema:Article ;
	schema:about wd:Q42 ;
	schema:inLanguage "en" ;
	schema:isPartOf <https://en.wikipedia.org/> ;
	schema:name "Douglas Adams"@en ;
	wikibase:badge wd:Q17437798 .
```

The page is not a Wikidata entity, so the title stays a value node `"Douglas Adams"@en` in a standard statement concerning the page’s IRI node ([Which Predicates Make a Name](names.md#which-predicates-make-a-name)), regardless of the order of the triples. Sitelinks carry Wikibase’s canonical language codes, such as `en-simple` for the Simple English Wikipedia; labels keep the codes from the JSON.

Descriptions (`schema:description`) and aliases (`skos:altLabel`) never become names: a node has a single name per language, with its label assuming that role, and aliases frequently appear in multiple instances within a language. When an import selects their languages, they become value nodes bearing their respective tags; by default, it keeps the labels in `en` and `mul` and excludes any descriptions or aliases, just as the JSON import does today, and counts what it drops ([D12](decisions.md#d12), [Parameters](import.md#parameters)). Among the labels that cannot become names, Wikidata includes only those whose spelling matches core nodes ([Labels That Do Not Become Names](names.md#labels-that-do-not-become-names)).

## Literal Values in Networks Built from the JSON Dump

The networks published today hold no literal values. The values of selected properties arrive at them through two distinct methods, which may be used together; each method produces the same value node for any given value.

### Two Ways In

**The RDF reader with selected predicates**, into a loaded network: `.import-rdf` with `identity=http://www.wikidata.org/` and `predicates=` ([Parameters](import.md#parameters)). From the truthy dump it adds simple values beneath the bare properties. Full values are accompanied by the statement layer, and there a constraint applies: Wikibase writes a full value node’s description solely when a lossy cache of hashes, maintained throughout a whole dump run, first meets the value, typically under a different property. A reader keeping the full values of P569 encounters descriptions before determining whether a P569 link will utilize them, thus in a single pass it either retains all of them or loses some, and a pipe does not allow a second pass. Besides, the dumps come from runs days apart – the index of 4 November 2026 listed `latest-all.json.gz` from 27 October and `latest-all.nt.gz` from 30 October 2026 – and mixing them attaches values from one revision to the structure of another without warning; dumps from one week should remain together. The RDF records each entity’s revision as `schema:version`, the JSON as `lastrevid`.

**A value pass of the JSON importer**, `.wikidata-values <dump> P… [ranks=]`, reads the dump from which the network was constructed, or one of its week, and writes the values of the listed properties using the same mapping. It creates no subject, thus a pruned network stays pruned; a missing object, such as a unit, is created as a bare node in `wikidata` and counted. `ranks=all`, the default, writes every rank, `ranks=best` what the truthy form holds.

### Direct Full-Value Facts

At a statement node, a full value incurs a cost ranging from three to four times that of a single fact from the entity to the value: one node named by the statement’s id and two facts substitute for the single fact (computed from the costs per unit in [Costs](costs.md#one-node-of-each-kind): 253 B and twice 132-178 B compared to 132-178 B; [D25](decisions.md#d25)). The value pass attaches it directly, in the form `S fv:P569 V`, where `V` is the `wdv:` node along with its description, and writes the values of other datatypes beneath the bare property, just as the truthy form does. Bach’s two dates of birth:

!!! example "Specified – not yet implemented"

    ```
    wd:Q1339 fv:P569 wdv:1361ec7a694d5e3d2da3cee9c2b11755
    (wd:Q1339 fv:P569 wdv:1361ec7a694d5e3d2da3cee9c2b11755) wikibase:rank wikibase:PreferredRank
    wd:Q1339 fv:P569 wdv:bb50079fb9bbc454270bf96c42174fd2
    wdv:1361ec7a694d5e3d2da3cee9c2b11755 rdf:type wikibase:TimeValue
    wdv:1361ec7a694d5e3d2da3cee9c2b11755 wikibase:timeValue "1685-03-31T00:00:00Z"^^xsd:dateTime
    wdv:1361ec7a694d5e3d2da3cee9c2b11755 wikibase:timePrecision "11"^^xsd:integer
    wdv:1361ec7a694d5e3d2da3cee9c2b11755 wikibase:timeTimezone "0"^^xsd:integer
    wdv:1361ec7a694d5e3d2da3cee9c2b11755 wikibase:timeCalendarModel wd:Q1985786
    ```

- **A predicate of its own.** `wdt:P569` is the bare `P569` ([D1](decisions.md#d1)): the objects beneath it would mix truthy literals and full values, a writer would emit `wdt:` triples with `wdv:` objects that Wikidata never writes, and a generic expansion of the objects of `P569` would set one day beside the true interval. `psv:P569` would mix entity and statement subjects. The predicate thus originates from zelph’s own namespace `https://zelph.org/ns/wikidata/full-value/`, named `fv:P569` in `wikidata` ([The Rows](iris.md#the-rows)); a writer expands `S fv:P V` into `S p:P G` and `G psv:P V` using a statement node it constructs.
- **Marks for rank.** The direct fact omits the statement node with rank and qualifiers, and checks skip deprecated and approximate values. The pass writes the fact for every rank and marks a rank other than normal with a statement about it, `(S fv:P V) wikibase:rank R`, `R` being the best rank among the statements of `P` at `S` that carry `V`, so a value shared by a normal and a deprecated statement is not marked deprecated. Sourcing circumstances (qualifier P1480) are marked similarly, `(S fv:P V) pq:P1480 C`.
- **On a network built from the RDF** the module `wikibase` derives the same facts and marks from the statement layer, via one rule per property generated from its declarations `P wikibase:claim C` and `P wikibase:statementValue SV`, shown below for P569. Checks are thus written once, against `fv:` facts ([Three Checks on Wikidata](checks.md)).

!!! example "Specified – not yet implemented"

    ```
    (S p:P569 G, G psv:P569 V) => (S fv:P569 V)
    ```

### The Values the Qualifier Layer Writes

Today `.wikidata-qualifiers` writes a qualifier’s value and its statement’s main value as a name in `wikidata`: a timestamp as the dump spells it (`+2020-01-01T00:00:00Z`), an amount without unit and bounds (`+42`), a text without its language, no coordinate ([Data Model](../qualifiers.md#data-model)). Such a name serves as the node for anything spelled alike: the string `"Q5"` is the item Q5, and a value spelled like a core node resolves to that core node. With the mapping, the layer writes value nodes and full values, `pq:` and `pqv:`, using the same mapping, and statement nodes in the RDF form ([D25](decisions.md#d25)). No switch keeps the old names: what they dropped cannot be recovered, no published network holds such a value (the qualifiers of `wikidata-20260309-all-P11260.bin` are items), and every network is regenerated for the release.

## One Mapping for Both Routes

The JSON importer emits the terms of Wikidata’s RDF using the code that RDF readers rely on ([D35](decisions.md#d35)). One function translates each term into its corresponding node for every reader and every pass of the JSON importer – an IRI via the namespace table, a blank node through the document’s identity, a literal through the content index. Ahead of it, a port of Wikibase’s value builders turns each JSON value into the export’s terms, following the rules outlined in the sections above. It selects based on the datatype of the snak’s property, not on the JSON value’s type, which is `string` for strings, identifiers, URLs, files, mathematical expressions, and musical notation alike, and defaults to this type when a dump line lacks the datatype, as Wikibase does for a deleted property. It reads nothing that the dumps lack – no hash of a main or reference snak, no URL of a sitelink – and computes what is required, such as the hash of an unknown value.

**"By construction" covers the node for equal terms**: two routes that produce one term converge on a single node, as a single function maps both. Whether they produce the same term – lexical form, `wdv:` name, description of a full value node – rests on the port faithfully reflecting the Wikibase version it tracks, a condition the [differential test](#the-differential-test) checks.

### The Name of a Full Value

Wikibase names a full value node based on an md5 hash: for a time or a quantity, of the serialization PHP produced up to version 7.3 for the value object, which its library of values reproduces for this purpose; for a coordinate, of latitude, longitude, precision, and globe concatenated with `|`. For Douglas Adams’s date of birth the hashed text is

```
C:20:"DataValues\TimeValue":80:{["+1952-03-11T00:00:00Z",0,0,0,11,"http:\/\/www.wikidata.org\/entity\/Q1985727"]}
```

with the md5 `426df9023763f08b066f4478480f44cd`, the node quoted above. It holds the JSON’s timestamp as it is, the time zone, `before`, `after`, the precision and the calendar; that of a quantity holds amount, unit and bounds; Neckertal’s coordinate hashes as `47.333333333333|9.1333333333333|0.1|http://www.wikidata.org/entity/Q2`, in PHP’s 14 digits, to `a35185bc…`.

The JSON route computes this hash ([D25](decisions.md#d25)), before substituting the unit "1" with `Q199`, even though Wikibase gives "no guarantee of the value of the hash except for the fact that different values will be represented by different hashes, and same value mentioned in different places will have the same hash" (Wikibase’s RDF dump format). A content key originating from zelph’s own design fails on the RDF route, which includes only the `wdv:` IRI and a description lacking `before` and `after` fields and containing the cleaned timestamp: a key from it merges what Wikibase keeps apart, such as Julian 30 February and 1 March 1700, or the unit "1" and the IRI of `Q199` (hashes `4d4bb312…` and `64346ed9…` for 113). The JSON holds every field of the hash, the computed hashes matched all 178 full value nodes across the nine exports, and the differential test watches the details of PHP’s serialization that the choice depends on.

### What Differs by Design

The routes continue to vary in content whenever a decision specifies such a difference. Equality between two networks is established based on their facts written as names within `wikidata` or as IRIs, with value nodes compared by content, as node identifiers originate from a counter.

| Content | JSON route | RDF route |
|---|---|---|
| ranks | every rank; marks at the direct full-value facts | truthy: the best; full: every statement with its rank |
| full values | direct facts `S fv:P V` | the statement layer, and `fv:` facts derived from it |
| snapshot | the run of the JSON dump | the run of the RDF dump |
| mathematical expressions | TeX, `<https://zelph.org/ns#TeX>` | MathML |
| normalized quantities | none | `psn:`, `pqn:`, `prn:`, `wikibase:quantityNormalized` |
| normalized identifiers | derived on request from P1921 | `wdtn:`, `psn:`, `pqn:`, `prn:` |
| statement nodes, qualifiers, references | statements with a selected qualifier (`.wikidata-qualifiers`) | every statement of the full form |
| declarations of properties | none | `wikibase:directClaim`, `wikibase:claim` and the others |
| sitelinks | not covered yet | `schema:Article` blocks |
| lexemes | not covered: items and properties only | blocks of lexemes, forms and senses |
| revisions and counts | none | the `data:` node of each entity |

The first six rows are decisions made on this page, accompanied by their reasons above; sitelinks would need Wikibase’s table of sites featuring its canonical language codes. The Wikidata Query Service falls beyond the requirement: its outputs express numbers in canonical form (`774` instead of `+774`) and unknown values as IRIs.

## The Differential Test

The test makes "the same value node on both routes" executable ([D35](decisions.md#d35)). Its data consist of pairs exported by `Special:EntityData` for pinned revisions: `<id>.ttl?revision=R&flavor=dump` and the JSON representation of the same revision. The flavour `dump` activates Wikibase’s full dump settings along with those for version information, meaning an export comprises the entity’s block from the dump, plus licence and software version details, and additionally includes descriptions of values and references that a dump run writes only upon their initial occurrence, using a single cache shared across all entities.

**Fixtures** live in `src/test/wikidata_pairs/`: for each entity, the dump line, rebuilt from the JSON without the hashes of main and reference snaks or the URLs of sitelinks, stored as `.json`, which `.load` hands to the Wikidata importer; the Turtle as fetched; and a manifest containing revision, time of fetching, the sha256 of the responses, the Wikibase version reported by the site, and the datatypes of the properties employed, alongside tables of the P1921 patterns and of the sites. `tools/wikidata_pairs.py` performs the refreshes; the test is `test_wikidata_routes.cpp`. Approximately fifty small entities, across them, encompass every scenario on this page; famous entities, whose exports are large, are reserved for the slow tests.

**What is compared.** One engine loads the dump lines using `.load` and runs the value pass to each property; another imports the Turtle under the identity `http://www.wikidata.org/` with identical label languages and derives the `fv:` facts. Both render their facts alike – names in `wikidata` or as IRIs, value nodes in Turtle form, blank nodes by label – and the test counts per class what both share and what only one possesses, with exact expected counts for every class this page excludes: mathematical expressions, normalized quantities (by the kind of object, since `psn:`, `pqn:` and `prn:` also carry identifiers’ IRIs), sitelinks and lexeme and property blocks while they are not covered, and the version triples. A second check imports the Turtle into the first engine and requires no new fact or value node in the covered classes.

**What it catches**: every place where the port deviates from Wikibase’s behaviour – a date that has been cleaned differently, a digit within a coordinate, a hash, an encoded URL, the label of a blank node – and every modification to Wikibase itself.

**It fails intentionally when Wikibase undergoes changes.** An export renders an outdated revision using today’s code, tables, and property datatypes, resulting in a pair that is consistent in itself but not the historical dump line. Wikibase does modify these aspects: the code read for this page rewrites the clamp for excessively long years to accommodate a newer PHP version (Phabricator T409269). When the test fails due to such a cause, fixtures and port are refreshed together.
